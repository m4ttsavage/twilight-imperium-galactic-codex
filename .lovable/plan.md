

# User Accounts and Game History for Galactic Codex

## Overview

This plan adds user authentication (Google + email/password), user profiles, and a game history system so players can log past TI4 games and review starting board states, factions, nicknames, and full standings.

## What You'll Get

- A **login page** with Google sign-in and email/password registration
- A **user profile page** showing your email and game history
- A **"Save Game" button** on the Map Generator to record a completed game
- A **game history list** where you can click into any past game to see the full board, factions, nicknames, and final standings
- Each user gets a unique account linked to their login email

## Feature Walkthrough

### 1. Login Page (`/auth`)
- Google sign-in button (one click)
- Email/password form with login and sign-up tabs
- Styled to match the dark space theme of the app
- After login, redirects to the home page
- Validation on email format and password length

### 2. Navigation Updates
- Add a user avatar/login button to the header on every page
- When logged in: show avatar icon linking to `/profile`
- When logged out: show "Sign In" link to `/auth`

### 3. User Profile Page (`/profile`)
- Shows your email and account creation date
- Lists all your saved games in reverse chronological order
- Each game card shows: date, player count, map string preview, and winner
- Click a game to expand and see the full board + standings
- Sign-out button

### 4. Save Game Flow (on Map Generator)
- New "Save Game" button appears when a user is logged in
- Opens a dialog to enter final standings:
  - For each slice/player: final VP score and placement (1st, 2nd, 3rd, etc.)
  - Winner is auto-selected as placement #1
  - Optional notes field
- Saves the map string, faction assignments, nicknames, and results to the database

### 5. Game Detail View
- Clicking a saved game shows:
  - The full hex map (re-rendered from the saved map string)
  - Faction assignments with icons and nicknames
  - Final standings table (placement, faction, player name, VP score)
  - Date played and any notes

## Technical Details

### Database Schema (3 new tables)

**profiles** - stores basic user info
- `id` (UUID, primary key, references auth.users)
- `email` (text)
- `display_name` (text, nullable)
- `avatar_url` (text, nullable)
- `created_at` (timestamp)
- `updated_at` (timestamp)

A trigger on `auth.users` inserts a profile row automatically on signup.

**games** - stores each saved game session
- `id` (UUID, primary key)
- `user_id` (UUID, references profiles, not null)
- `map_string` (text, not null) -- the tile ID string
- `player_count` (integer, not null)
- `notes` (text, nullable)
- `played_at` (timestamp, defaults to now)
- `created_at` (timestamp)

**game_players** - stores per-player data for each game
- `id` (UUID, primary key)
- `game_id` (UUID, references games on delete cascade)
- `slice_index` (integer, not null)
- `faction_name` (text, nullable)
- `nickname` (text, nullable)
- `placement` (integer, nullable) -- 1 = winner, 2 = second, etc.
- `victory_points` (integer, nullable)

### Row-Level Security

All three tables have RLS enabled:
- **profiles**: Users can read and update only their own profile
- **games**: Users can read, insert, and delete only their own games
- **game_players**: Users can read/insert/delete game_players for games they own (via a join to games.user_id)

### Auth Configuration
- Google OAuth via Lovable Cloud managed solution (uses `lovable.auth.signInWithOAuth`)
- Email/password via standard `supabase.auth.signUp` / `supabase.auth.signInWithPassword`
- Auto-confirm email is left disabled (users verify via email) unless you request otherwise
